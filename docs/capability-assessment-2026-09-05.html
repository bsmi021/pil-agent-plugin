Repository assessment • 5 September 2026 • version 0.8.0 • source commit dbedca0

Improve the measurement foundation, then expand the agent toolbox

The plugin already has a strong quantitative core. The highest-value additions are colour-managed input handling, explicit region masks, controlled registration, domain-specific calibration, and a discoverable tool interface. Larger vision models belong in optional, separately evaluated extensions.

This is an analysis and recommendation document, not an implementation plan or release certification. Findings combine live source inspection, three isolated probes, and primary-source research. Existing repository validation results are historical evidence; they were not rerun here. No runtime code, dependencies, or existing tests were changed.

Directly observed accuracy gaps

1. Stored pixels and displayed appearance can disagree

scripts/pil_common.py:load_rgba_straight opens and converts pixels directly. It does not apply EXIF orientation or an ICC transform. pil_image_info explicitly treats ICC as metadata; pil_color assumes sRGB input. A generated JPEG tagged with EXIF orientation 6 loaded as 60×30 through the plugin, while Pillow's display-orientation transform produced 30×60.

Recommendation: introduce explicit stored-pixel and display-normalized modes, using ImageOps.exif_transpose and ImageCms/LittleCMS. Record source profile hash, assumed profile when absent, output colour space, rendering intent, orientation and coordinate transforms. Keep alpha separate through colour conversion. Preserve existing thresholds and defaults until a new pipeline is calibrated. ICC handling was established by source inspection, not a colour-profile numerical benchmark.

2. Embedding claim eligibility omits preprocessing

pil_embed compares preprocessing between two descriptors, but capability lookup and model_gated depend on model hash alone. A synthetic saved-descriptor probe using the known CLIP hash and ImageNet preprocessing returned no flags and the CLIP capability advertisement. This verified the metadata/claim path only; no model inference was performed.

Recommendation: key validation claims by model hash plus the complete preprocessing specification and relevant output identity. A known model with the wrong profile should be rejected or reported as an unvalidated configuration, even if both compared files share it. Expose capabilities and evidence identifiers as structured fields, rather than requiring agents to interpret long prose.

3. Full rank does not establish a stable reconstruction

pil_multiview_solve:_constraint_rank reports rank and deficiency. Two nearly parallel synthetic views passed that check with rank 3/3 while the observation matrix had a condition number of approximately 200,000,000. This probes rank only; it does not assert that a full solve returned SOLVED.

Recommendation: report singular values, conditioning, weakly observed directions, and sensitivity to landmark noise. Use known or caller-supplied observation uncertainty before emitting uncertainty intervals. Add a refusal or warning for unstable geometry; regularization must remain separate from observational evidence.

Recommended additions, in priority order

Names below are proposals, not existing commands. Effort is relative engineering complexity, not a delivery estimate.

2 · pil_maskAccept caller-supplied raster masks and polygons, combine/subtract regions, name parts, and retain image hash and coordinate provenance. 3 · pil_registerEstimate bounded translation first; offer rigid/affine registration only when the comparison permits it. 5 · pil_diff_regionsAdd native-resolution local ΔE maps, multiple change boxes, magnified crops and optional standard SSIM. Current change localization returns an enclosing box and can dilute small defects in working-resolution summaries.Detect controlled small defects while separating resampling/JPEG/antialiasing controls. Version and calibrate new metrics independently. Medium.
6 · pil_capabilities and optional MCP adapterExpose available tools, argument/output schemas, dependency readiness, calibrated versus diagnostic status, costs and required inputs. Wrap existing functions once for CLI and MCP; support batch jobs and compact summaries with artifact links.Parity with existing CLI outputs and refusal states. Distinguish read-only probes from copy-writing/fitting operations. Keep per-item failures in batches. Medium.
7 · Surface-level geometry checksExtend Blender probes with evaluated garment geometry, triangle-intersection tests, adaptive surface samples and world-space clearance. Current code queries an evaluated body BVH but iterates garment data vertices.Include a case where a triangle crosses the body although its vertices are outside, modifier/pose changes, nonuniform scale and inconsistent normals. Report sampling bounds; finite samples cannot certify arbitrary surfaces. Medium–large.
8 · Camera and uncertainty toolsAdd camera calibration/import, reprojection diagnostics and perspective-aware projections as a versioned extension. OpenCV supports calibration with per-view errors and parameter deviation estimates.Known-camera synthetic scenes plus held-out real calibration images; explicitly detect poor view geometry and uncertain scale. This requires a solver/schema extension, not a drop-in camera matrix. Large.
9 · OCR preparation and text comparisonAdd deskew/orientation, selected thresholding variants, preprocessing provenance and box-preserving text diffs. Tesseract and page-segmentation selection already exist.Measure character/word error and coordinate mapping on small, rotated and low-contrast text. Do not select a preprocessing variant solely on the engine's confidence value. Medium.
10 · Sequence and texture inspectionAdd frame/atlas manifests for jitter, alpha-bound clipping, duplicate/blank frames and loop seams; optional texture checks for seams, channel ranges and normal-map conventions.Known frame faults and caller-declared texture semantics. Intentional repeated frames or stylistic seams must not automatically become defects. Medium.

Registration references: OpenCV ECC and scikit-image registration. Local metrics: scikit-image metrics. Agent interface: MCP tool schemas and structured results. Camera extension: OpenCV calibration. OCR: Tesseract quality guidance.

Optional models worth evaluating

  • Prompted segmentation, such as SAM 2: lets an agent select an object or garment with points/boxes on cluttered backgrounds. Establish the mask contract first, then use model masks as revisable proposals. It adds substantial dependencies; the official project recommends WSL on Windows. Official SAM 2 repository.
  • LPIPS: a candidate for perceptual appearance differences that simple statistics miss. Useful as a separately named metric with task-specific evaluation, never as a universal match percentage. Official implementation.
  • DINOv2 features: a candidate for region/patch matching and instance-oriented retrieval alongside existing CLIP descriptors. Superiority on this plugin's asset corpus remains unmeasured; compare identical hard-negative and perturbation families before selecting it. Official implementation.

These are concrete candidates with documented capabilities, not a claim that they are the latest or best models. Keep weights caller-selected and hash-pinned, include preprocessing in the validation key, and record runtime and benchmark scope. A heavyweight 3D dependency should likewise be optional: Open3D distance queries are useful, but signed-distance interpretation depends on mesh assumptions. Reusing Blender first is the lower-integration-cost choice.

Recommended investment

First fix input comparability and model/profile claim eligibility. Then add explicit masks, controlled registration, local change regions and domain calibration. Add machine-readable discovery early so calling agents can reliably use the expanded surface. Pursue surface geometry and camera uncertainty where 3D workflows justify them. Benchmark optional learned metrics only after these foundations are stable.

The success measure should be fewer false alarms, fewer missed task-relevant defects, and fewer invalid comparisons on held-out inputs. More metrics or higher similarity scores alone do not establish an improvement.
